# Auditoria inicial do aplicativo legado

Escopo: leitura estática do cliente Rangulos no commit `c7b51e1` e da API de primeira parte [ViniciusRio/Rangulos-API](https://github.com/ViniciusRio/Rangulos-API/tree/d118a5e68be386da31c31839a6dd4882c971d84b) no commit `d118a5e` (consultado em 2026-10-13). As referências `src/...` são deste repositório; `API:...` apontam para arquivos do commit vinculado da API. Esta auditoria descreve código e contrato observáveis. Gravidade e impacto abaixo são prioridades de investigação, não confirmação de exploração. Não foram executados testes de integração nem provas de exploração.

## Comportamento do cliente

1. O aplicativo abre na rota `/`, que carrega a página inicial sem guarda; `/home`, `/events`, `/events/:id` e `/new` têm `canLoad` baseado apenas na presença de `token` no `localStorage`. Sem token, o guarda redireciona para `/auth`. As rotas `/auth` e `/register` são públicas. `src/app/app-routing.module.ts:5-40`; `src/app/auth/auth.guard.ts:15-21`; `src/app/auth/auth.service.ts:18-25`.
2. Registro envia `name`, `email` e `password` e, em sucesso HTTP, oferece voltar ao login. Login envia `email` e `password` (com `name` indefinido nesse formulário), grava o `token` retornado e navega para `/home`. O cliente também marca `userAuthenticate = true` quando a resposta de login **não** contém `token`, desde que seja um sucesso HTTP. `src/app/register/register.page.ts:26-64`; `src/app/auth/auth.page.ts:57-95`; `src/app/auth/auth.service.ts:28-45`.
3. A página inicial busca eventos ao entrar, aceita pesquisa textual `q` com debounce de 500 ms, atualiza ao puxar para baixo, exibe preço/datas/selo de pago e leva ao detalhe ou à criação. Erros da busca viram lista vazia na interface. `src/app/home/home.page.ts:28-52`; `src/app/home/home.page.html:8-53`.
4. O menu oferece Início, Meus eventos, Eventos atuais e Eventos anteriores. A página `/events` alterna esses três segmentos, carrega a lista respectiva e permite suspender/restaurar eventos próprios. A API define "atuais" como convites do usuário cujo evento ainda não terminou, "anteriores" como convites pagos de eventos encerrados, e "meus" como eventos criados pelo usuário, inclusive suspensos. `src/app/app.component.ts:21-45`; `src/app/events/events.page.ts:53-107,132-223`; `src/app/events/events.page.html:10-20,65-137`; `API:app/Http/Controllers/EventController.php:247-314`.
5. Criar evento coleta título, descrição (máximo de 100 caracteres no cliente), endereço, preço, lotação e datas; envia um objeto `Event` e abre o detalhe do `id` retornado. Há um botão de preenchimento de dados que chama `/events/fill`; apesar do diálogo dizer "três eventos", o controlador insere quatro eventos estáticos com datas de 2019 e um convite com IDs fixos. `src/app/events/new-event/new-event.page.ts:24-85,109-129`; `src/app/events/event.model.ts:1-18`; `src/app/events/new-event/new-event.page.html:119-122`; `API:app/Http/Controllers/EventController.php:84-147`.
6. O detalhe obtém o evento por ID e mostra anfitrião, endereço (abre Google Maps), horários, capacidade e convidados. Para o proprietário, habilita edição, envio de imagem e exclusão definitiva; para outro usuário, oferece garantir convite, pagar, desistir e, após o fim, avaliar. O botão de pagamento apenas chama a API e marca o convite como pago no banco; não há integração de cobrança nesse fluxo observado. `src/app/events/event-detail/event-detail.page.ts:36-105,107-195,197-324`; `src/app/events/event-detail/event-detail.page.html:19-128`; `API:app/Http/Controllers/EventController.php:319-335`.
7. O perfil exibe nome e e-mail da API e uma foto de `picsum.photos`; sair chama `/logout`, limpa `localStorage` e volta a `/auth`. O menu também busca `/user` ao inicializar, mesmo antes de verificar se existe token. `src/app/profile/profile.page.ts:21-72`; `src/app/profile/profile.page.html:16-29`; `src/app/app.component.ts:61-91`.

## Contrato HTTP observado

Base URL atual: `http://localhost:8081/api` em desenvolvimento **e** produção. A URL Heroku em produção está comentada; o build de produção substitui o arquivo de ambiente. `src/environments/environment.ts:5-9`; `src/environments/environment.prod.ts:1-7`; `angular.json:44-51`. A API acrescenta o prefixo `/api` às rotas em `API:app/Providers/RouteServiceProvider.php:66-72`.

As rotas da API não declaram middleware `auth`; a autenticação ocorre dentro dos controladores. `API:app/Http/Controllers/AuthController.php:41-52,82-88`; `API:routes/api.php:3-29`; `API:app/Http/Kernel.php:42-45`; `src/app/events/events.service.ts:12-18,30-38`.

## Matriz de riscos para investigação

As gravidades priorizam revisão e testes futuros. Elas não afirmam que um ataque foi realizado ou que o comportamento ocorre em produção.

| Prioridade | Risco | Evidência estática | Impacto potencial | Recomendação |
| --- | --- | --- | --- | --- |
| Alta | Autorização de ações sobre eventos no backend | `update`, `destroy`, `restore`, `upload` e `deleteEvent` obtêm usuário autenticado, mas não mostram checagem de propriedade antes da alteração; `update` redefine `user_creator_id`. `API:app/Http/Controllers/EventController.php:197-242,341-366,409-433`. | Se as rotas estiverem acessíveis e não houver proteção em outra camada, um usuário autenticado poderia modificar dados de evento alheio. | Mapear políticas de acesso por ação, aplicá-las no backend e verificar com testes de autorização para proprietário e não proprietário. |
| Alta | JWT em URLs | O cliente envia `?token=<JWT>` em `/user`, `/logout`, consultas e alterações de eventos; a URL de imagem também contém o token. `src/app/auth/auth.service.ts:47-74`; `src/app/events/events.service.ts:30-245`. | URLs com token podem aparecer em logs de acesso, monitoramento, caches ou compartilhamentos, conforme a infraestrutura usada. | Definir transporte de autenticação fora da URL, revisar registros e caches, e validar a troca de contrato cliente/API antes de alterar o fluxo. |
| Alta | Integridade do estado de pagamento | O detalhe calcula `is_paid` a partir de qualquer convidado pago; `/event/pay` marca `payment_confirmed = true` para o convite do usuário sem evidência de cobrança externa. `API:app/Http/Controllers/EventController.php:155-188,319-335`; `src/app/events/event-detail/event-detail.page.html:90-110`. | A interface pode esconder a ação de pagar de quem ainda não pagou e apresentar confirmação incompatível com uma cobrança real. | Validar a regra de cobrança e o estado por convidado; separar confirmação financeira de ação do usuário e cobrir cenários com vários convidados. |
| Alta | URL de produção | `environment.prod.ts` aponta para `http://localhost:8081/api`, igual ao ambiente de desenvolvimento; a URL remota está comentada. `src/environments/environment.prod.ts:1-7`; `src/environments/environment.ts:5-9`. | Um app instalado em dispositivo tende a procurar a API no próprio dispositivo, impedindo os fluxos dependentes do backend; HTTP também não protege o tráfego em trânsito. | Definir endpoint de produção acessível por HTTPS e verificar configuração em build e dispositivo antes de qualquer publicação. |
| Média, dependente da política | Proteção de dados de eventos | `show` usa ID e retorna endereço e dados do anfitrião sem filtro de visibilidade ou participação visível no método; a busca retorna eventos futuros. `API:app/Http/Controllers/EventController.php:27-48,155-188`. | Se endereço ou detalhes forem reservados a participantes, usuários autenticados podem recebê-los antes do momento pretendido. A política ainda não está definida. | Validar visibilidade e divulgação da localização com o responsável pelo produto; então aplicar filtro no backend e testar os estados de participação. |

## Dependências e pontos a confirmar

- O cliente precisa da API Laravel e de seu banco/armazenamento para quase todos os fluxos. A API define tabelas `events` e `guests`, JWT, upload no armazenamento local, e arquivos servidos pelo próprio endpoint de imagem. O endereço `localhost` no app móvel aponta para o próprio dispositivo; a configuração não demonstra uma URL utilizável fora da máquina do servidor. `API:database/migrations/2019_10_29_233927_create_events_table.php:16-30`; `API:database/migrations/2019_10_29_233953_create_guests_table.php:16-25`; `API:app/Http/Controllers/EventController.php:357-403`; `src/environments/environment.prod.ts:1-7`; `capacitor.config.json:10-15`.
- A página de detalhe depende de campos calculados pela API (`is_owner`, `is_guest`, `is_paid`, `total_guests`, `user_creator`, `guests`), além dos campos persistidos. O cálculo de `is_paid` usa **qualquer** convidado pago do evento, enquanto `is_guest` usa o usuário atual; isso pode fazer o botão Pagar desaparecer para um convidado ainda não pago. Confirmar a regra de negócio antes de tratar o campo como pagamento individual. `src/app/events/event-detail/event-detail.page.html:67-71,90-123`; `API:app/Http/Controllers/EventController.php:155-188`.
- A API de edição redefine `user_creator_id` para o usuário que chamou o endpoint e não verifica propriedade nesse método; suspensão, restauração, upload e exclusão também não mostram checagem explícita de propriedade. A interface oculta essas ações por `is_owner`, mas a autorização real do backend precisa ser validada. `API:app/Http/Controllers/EventController.php:197-219,227-242,341-366,409-433`; `src/app/events/event-detail/event-detail.page.html:6-9,20-27,111-115`.
- A avaliação é enviada sem aguardar resposta ou atualizar a tela; o detalhe retornado pela API não inclui `rate`, embora o template o leia. O upload salva o arquivo como `{id}.jpg` sem validação de tipo visível no controlador. `src/app/events/event-detail/event-detail.page.ts:190-195`; `src/app/events/event-detail/event-detail.page.html:90-100`; `API:app/Http/Controllers/EventController.php:170-188,357-375`; `API:app/Http/Controllers/GuestController.php:70-82`.
- O módulo de abas declara apenas uma rota filha de perfil e não aparece nas rotas principais; a tela de edição alternativa `edit-my-events` está vazia. O fluxo efetivo observado usa menu lateral e modal de edição. `src/app/app-routing.module.ts:5-41`; `src/app/tabs/tabs.module.ts:11-24`; `src/app/events/edit-my-events/edit-my-events.page.ts:27-30`; `src/app/events/event-detail/event-detail.page.ts:47-65`.
- Não há evidência de contrato de erros, validação de capacidade, datas ou pagamento real suficientemente documentado para assumir comportamento além do código acima. Próxima auditoria deve executar cliente e API juntos com dados de teste e registrar respostas reais dos endpoints, especialmente autenticação via query string e os estados de convite/pagamento.
